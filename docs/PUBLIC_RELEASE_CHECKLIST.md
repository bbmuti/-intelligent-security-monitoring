# Public Release Checklist

The repository should remain private until every blocking item is checked.

## Blocking checks

- [ ] GitHub Actions is green on `main`.
- [ ] Repository history contains no real passwords, API keys, tokens, private URLs, personal data, or production logs.
- [ ] `.env`, databases, downloaded datasets, coverage output, and build output remain ignored.
- [ ] Every screenshot contains synthetic identities and documentation-reserved IP addresses only.
- [ ] Demo credentials are not reused anywhere else.
- [ ] Dependency licenses are compatible with an MIT-licensed repository.
- [ ] README limitations and security boundary still match the implementation.
- [x] Published BETH metrics were generated by `benchmark_beth.py` and include all three input hashes.
- [ ] Private vulnerability reporting is enabled before inviting external users.

## Presentation checks

- [ ] Add two current dashboard screenshots produced from the running application.
- [ ] Record the 90-second flow in `DEMO.md` without exposing local secrets or browser bookmarks.
- [ ] Add repository topics: `cybersecurity`, `fastapi`, `react`, `isolation-forest`, `siem`, `mitre-attack`, `postgresql`, `docker`.
- [ ] Add the final public repository URL to the Turkish and English CV entries.

## Visibility change

Changing GitHub visibility is a separate, deliberate action. Re-run the complete test and secret-scan suite immediately before making the repository public.
